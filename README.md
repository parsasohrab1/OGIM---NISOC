# OGIM — Marun Field Deployment (NISOC)

This repository is a **complete, independent copy (fork)** of the product [OGIM — Oil and Gas Field Smartification](https://github.com/parsasohrab1/OGIM---Oil-Gas-Intelligent-Monitoring), localized for a demonstration deployment on the **Marun field**, one of the fields of the **National Iranian South Oil Company (NISOC)**.

## 🎯 Technology Readiness Level (TRL) Status

**Current TRL**: **4** (evaluated on REAL field data with fixed methodology)

**Latest Evaluation** (2026-11-09, 20 instances/class, v6_optimized):
- ✅ **Leakage audit:** PASSED (per-sample labeling, well-grouped splits, balanced training, missing-class check)
- ❌ **Detector is degenerate (TN=0):** Predicts event 100% of the time; 1440 false alarms/day
- ❌ **TRL5 Criteria:** Failed Binary Macro-F1 (0.446 < 0.65) and False Alarms/Day (1440 > 3.0)
- ⚠️ **No practical discrimination:** Recall and lead time are trivial artifacts of always alarming

**Verdict:** TRL4 maintained. Methodology is sound but detector provides no operational value; requires feature engineering redesign.

## Data status — important

The data in this repo is **synthetic/demonstration data**, not real, confidential Marun field data. The architecture, service logic and data model are fully real and functional, but sensor values (pressure, temperature, flow rate, vibration, etc.) are generated by a deterministic (seeded pseudo-random) generator — exactly the same pattern used for the Dehloran field in the main product, reproduced here with Marun field parameters and branding. Connecting to real Marun field data and sensors requires a separate integration with NISOC's real SCADA/Historian, which is outside the scope of this fork.

**🆕 Real Field Data Validation**: The [Petrobras 3W](https://github.com/petrobras/3W) dataset was used for validation against real data. Details are in the [validation report](docs/validation-real-data.md).

## Why a separate repo, independent of the Dehloran field?

- **Fully independent storage**: This fork has its own infrastructure (PostgreSQL, TimescaleDB, Kafka, Redis) and code; it shares no data or database with the Dehloran field sample.
- **Complete localization**: All 9 local data modules (`marunField`, `marunAlerts`, `marunScada`, `marunDvr`, `marunRul`, `marunAr`, `marunMl`, `marunLstm`, `marunFederated`) and all front-end pages were rewritten for the Marun field: 24 wells with IDs `MRN-01`…`MRN-24`, NISOC as the client, a sour light-to-medium crude with an API gravity of ≈34.5, and the Asmari–Bangestan reservoir (demonstration depths of 2800 to 4300 m).

See `docker-compose.dev.yml` for the full details of each service and its ports.

## Offline/demo run (without a back end)

```bash
cd frontend/web
npm install
npm run dev:offline
```
Then open `http://localhost:3000`. The dashboard works fully offline with Marun field demo data — exactly matching the "try the real API → local fallback" behavior implemented in the main product.

## Full run with the back end

```bash
docker compose -f docker-compose.dev.yml up
```
All services (back end, Kafka, PostgreSQL/TimescaleDB, Redis, Prometheus/Grafana) come up from this repo alone, completely independent of any other deployment.
